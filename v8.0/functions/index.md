# Functions

- [OpenAPI specification](functions.yaml)
- [Functions](operations/getFunctions/operation.md)
  - To retrieve a paginated list of all [functions](https://www.zoho.com/crm/developer/docs/functions/overview/introduction.html) in your Zoho CRM account. The response contains metadata about each function, including its name, API name, runtime, category, state, arguments, tags, and timestamps. To get the implementation code of a function, you must use the [Download Function Code API](functions.yaml#$.paths./settings/functions/{fxIdentifier}/code.get).
  - [Examples](operations/getFunctions/examples/)
- [Function](operations/createFunctions/operation.md)
  - Use this API to create a function in your Zoho CRM account. Create Deluge, Java, Node.js, or Python functions with metadata and code. Deluge code can be JSON-embedded (`_code`) or uploaded as a .ds file; others require a ZIP package. **Note:** - Up to **20,000** functions per organization. - Deluge: provide code via `_code` or the `code` form-data .ds file; if both are given, `code` takes precedence. - If neither is given, the function is created as **active** with a default implementation, e.g. for **Cleanup Duplicates** (Standalone): string standalone.cleanup_duplicates() { return ""; } - Deluge declaration: lowercase function name (underscores for spaces) + lowercase category, e.g. **string standalone.restore_deal_by_name(...)**; return type must match the category default. - Java, Node.js, Python: upload a ZIP via `code`. On compilation errors, the function is saved as a draft and **207 Partial Success** is returned.
  - [Examples](operations/createFunctions/examples/)
- [Function](operations/getFunction/operation.md)
  - Use this API to retrieve the details of a specific [function](https://www.zoho.com/crm/developer/docs/functions/overview/introduction.html) in your Zoho CRM account by specifying its unique ID or API name. The response contains information such as the function's runtime, category, state, arguments, tags, REST API mode, and creation and modification details. To get the implementation code of the function, you must use the [Download Function Code API](functions.yaml#$.paths./settings/functions/{fxIdentifier}/code.get). You can obtain the function ID or API name using the [Functions API](functions.yaml#$.paths./settings/functions.get). **Note:** If the specified function ID or API name does not exist, the API returns an **HTTP 204 (No Content)** response with an empty response body.
  - [Examples](operations/getFunction/examples/)
- [Update a function by identifier](operations/updateFunction/operation.md)
  - Use this API to update an existing function in your Zoho CRM account. You can update the function name, description, code, and publish configuration. For **Deluge** functions, you can also update arguments by modifying the script's function declaration. The API name, runtime, and category cannot be updated. Get the function ID or API name using the [Functions API](functions.yaml#$.paths./settings/functions.get). **Note** - Deluge: provide code via `_code` or the `code` form-data .ds file; if both are given, `code` takes precedence. - The Deluge declaration must use the existing lowercase name (underscores for spaces) + lowercase category, or the API returns **COMPILATION_ERROR** (with line number, position, and message). - Java, Node.js, Python: upload a ZIP via `code`. If the update succeeds but publishing fails on compilation errors, the API returns **207 (Partial Success)** and the function stays unpublished.
  - [Examples](operations/updateFunction/examples/)
- [Function](operations/deleteFunction/operation.md)
  - To delete a function identified by its unique ID or API name from your Zoho CRM organization. The function can't be deleted if it has active references or associations, such as workflow rules, buttons, or schedules, references from other functions, or REST API exposure. Remove the references and associations, or disable the REST API exposure, before attempting deletion. You can obtain the function ID or API name using the [Functions API](functions.yaml#$.paths./settings/functions.get).
  - [Examples](operations/deleteFunction/examples/)
- [Download Function Code](operations/getFunctionCode/operation.md)
  - This API downloads the source code of the specified function. - **Deluge Functions:** A Deluge function consists of a single source file containing the function logic. When downloaded, the API returns the function as a **.ds file** with a maximum file size of **2 MB**. - **Multi-file runtime Functions:** **Java, Node.js, and Python** functions are packaged as projects that can contain multiple source files and folders, rather than a single source file. When downloaded, the API returns the function as a **ZIP (.zip)** package with a maximum file size of **25 MB**. You can obtain the function ID or API name using the [Functions API](functions.yaml#$.paths./settings/functions.get). **Note:** The above images show sample downloads for both Deluge functions and multi-file runtime functions (Java, Node.js, and Python).
  - [Examples](operations/getFunctionCode/examples/)
- [Publish a function](operations/publishFunction/operation.md)
  - This API is applicable only to **Java**, **Node.js**, and **Python** functions. The function must have an unpublished **draft** version before it can be published. **Deluge** functions are **automatically published** when they are created or updated and cannot be published using this API. Publish an existing draft of a **Java**, **Node.js**, or **Python** function in your Zoho CRM account. You can optionally specify a changelog message for revision tracking. To identify functions with unpublished drafts, use the [Functions API](functions.yaml#$.paths./settings/functions.get) and check whether the **has_draft** field is **true** ("has_draft": true).
  - [Examples](operations/publishFunction/examples/)
- [List Function Runtime](operations/getRuntimes/operation.md)
  - To retrieve the list of all supported function runtimes available in your Zoho CRM organization, including the programming language, runtime version identifier, and deprecation status for each entry.
  - [Examples](operations/getRuntimes/examples/)
- [Function Categories](operations/getCategories/operation.md)
  - To retrieve all the [Function](functions.yaml#$.paths./settings/functions.get) categories supported by the current Zoho CRM account and indicate whether each category is available for use. Different Zoho CRM editions and enabled features support different Function categories. Instead of assuming that a category is available, you can use this API to: - Discover all the Function categories supported for the current CRM account. - Check whether a Function category can be used before creating or updating a Function. For example, if a customer's Zoho CRM edition does not support the **Signals** Function category, the response shows that the category is unavailable.
  - [Examples](operations/getCategories/examples/)
